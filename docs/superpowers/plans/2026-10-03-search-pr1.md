# Keyboard and Global Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An on-screen keyboard and one global search over the user's library and the Spotify catalog, returning songs, albums, artists and playlists, each playable or openable.

**Architecture:** Everything goes through the pure app core like browsing does. Library matches are computed in `view` from state; catalog results come from a new `LibraryRequest::Search`. Artists open an album grid (Spotify forbids artist top tracks for developer apps) with a Play button for the artist context. The search screen is one flat list of rows, so a single `ListView` handles scrolling.

**Tech Stack:** Rust, Slint 1.18, tokio, reqwest, librespot 0.8.

**Spec:** `docs/superpowers/specs/2026-10-03-search-and-playlists-design.md` (PR 1). Changes agreed after the spec: artists are in; HTTP write support moves to PR 2, where it is first used.

**Verified against the live API (2026-10-03, developer-app token):** `GET /search?type=track,album,artist,playlist` → 200, with `null` entries mixed into `playlists.items`; `GET /artists/{id}/albums` → 200; `GET /artists/{id}/top-tracks` → 403; `GET /playlists/{id}/items` for playlists owned by others → 403.

Commands below assume `export PATH="$HOME/.asdf/shims:$PATH"` and run from the repo root. Test command for any task: `cargo test -q -p muzak-player <filter>`.

### Task 4: Core — keyboard, search debounce, artists, single-song play

**Files:** `src/app/input.rs`, `src/app/state.rs`, `src/app/mod.rs`, `src/app/tests.rs`.

State:

```rust
pub enum Screen { Grid(Section), Detail(String), NowPlaying, Search, Artist(String) }

#[derive(Debug, Clone, PartialEq, Default)]
pub struct SearchState {
    pub query: String,
    /// The query the catalog results belong to.
    pub sent: String,
    pub edited_ms: u64,
    pub results: Slot<SearchResults>,
}
// AppState gains: search: SearchState, keyboard_open: bool,
//                 artist_albums: HashMap<String, Slot<Vec<Collection>>>
// Slot gains: forbidden: bool  (fetch refused with 403 and no data to show)
```

Actions (`UiAction`): `KeyPressed(String)`, `Backspace`, `ClearSearch`, `OpenKeyboard`, `CloseKeyboard`, `OpenArtist(String)`, `PlayArtist(String)`, `PlaySong(String)` (a track URI from search). `Input::SearchTick`.

Behavior:
- `ShowSection(Search)`: section Search, back stack cleared, screen `Search`, keyboard open.
- `KeyPressed(s)`: append `s` to `query` (cap 100 chars), `edited_ms = now`. `Backspace` pops one char. `ClearSearch` empties query and results. All three only act while the screen is Search.
- `SearchTick` and `Tick`: when `query != sent` and `now - edited_ms >= 400`: if `query.trim()` is empty, clear results and set `sent`; else set `sent = query`, mark results loading, emit `LibraryRequest::Search(query.trim())`.
- `SearchResults { query }` is stored only when `query == sent.trim()`; stale ones are dropped. `SearchFailed` likewise sets `failed`, and `Offline` marks the app offline.
- `OpenKeyboard`/`CloseKeyboard` toggle `keyboard_open`. Leaving the Search screen (any navigation) closes it.
- `OpenCollection` from search works unchanged; Back returns to Search.
- `OpenArtist(uri)`: navigate to `Artist(uri)`, request `ArtistAlbums`. `PlayArtist(uri)`: `start_playback(uri, None, shuffle=false)`.
- `PlaySong(uri)`: find the track in `search.results.tracks` or any loaded track list. Context is its `album_uri` when known, else the track URI itself; `start_uri = Some(uri)`; `playback.track` is set at once so Now Playing shows it.
- `TracksFailed { reason: Forbidden }` sets `slot.forbidden = slot.data.is_none()` instead of `failed`.
- `wants_search_tick()` is true while `screen == Search`.

Tests (each its own `#[test]`): section opens keyboard; typing then 399ms sends nothing, 400ms sends one `Search("ab")`; a second tick sends nothing; backspace to empty clears results without a request; stale results dropped; results stored for the current query; `OpenArtist` requests albums and Back returns to Search; `PlaySong` loads the album with `start_uri` and sets the track; `PlaySong` without album uses the track URI; forbidden track list sets `forbidden` not `failed`; key presses ignored off the Search screen.

- [ ] Write the tests, see them fail, implement, see them pass. Commit `feat(core): keyboard, debounced search, artists`.
